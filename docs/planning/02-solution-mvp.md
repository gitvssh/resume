## 1. 한 줄 해결안

이 문서는 문제에 대한 해결 접근과 MVP 범위를 정의한다.

한 줄 요약:

`우리는 경력직 백엔드 개발자의 마스터 이력서를 채용공고 입력에 맞춰 재구성하고, 변경 근거와 diff를 함께 제공하는 도구를 v0로 먼저 제공한다.`

## 2. 해결 전략

문제를 어떤 방식으로 풀 것인가:

- 마스터 이력서와 JD를 각각 구조화한 뒤, JD와의 대응 관계를 분석해 맞춤 이력서를 생성한다.
- 사용자는 자동 생성 결과를 그대로 받는 것이 아니라, 수정 이유와 diff를 확인하고 직접 편집한 뒤 내보낸다.

이 접근이 적절한 이유:

- 핵심 pain point인 `공고별 맞춤 수정`을 직접 해결한다.
- 평가와 추천을 독립 제품으로 만들지 않고, 재작성 품질을 높이는 supporting capability로 둘 수 있다.

대안으로 고려했지만 이번에 택하지 않은 방식:

- 단순 첨삭 도구
- 공고 추천 중심 서비스
- 완전 자동 생성 후 바로 제출하는 방식

## 3. 핵심 가치 제안

사용자에게 즉시 주는 가치:

- 10분 안에 공고 맞춤 이력서 초안을 만든다.
- 어떤 경험을 왜 강조했는지 설명을 본다.
- 직접 수정 가능한 상태로 결과를 받는다.

기존 대안 대비 차이:

- 사람 첨삭보다 빠르고 저렴하다.
- 범용 챗봇보다 입력 구조, 근거, diff, PDF 출력이 명확하다.
- 로컬 모델 기반 처리 방향으로 개인정보 우려를 줄인다.

이 솔루션이 작동한다고 보는 근거:

- 사용자가 가장 원하는 산출물이 맞춤 이력서다.
- JD 대응 설명과 diff 제공은 신뢰성을 높인다.
- PDF 업로드 후 편집 가능한 텍스트 확인 단계를 두면 OCR/파싱 오류를 사용자 검토로 보완할 수 있다.

## 4. 핵심 사용자 흐름

시작 조건:

- 사용자가 PDF 이력서를 업로드한다.

사용자 행동:

1. 추출 텍스트를 확인하고 수정한다.
2. JD를 붙여넣거나 URL로 입력한다.
3. 맞춤 재작성 결과와 diff, 근거를 확인한다.
4. 필요한 부분을 수정한다.
5. PDF로 내보낸다.

시스템 반응:

- PDF에서 텍스트를 추출한다.
- Resume schema와 JD schema로 구조화한다.
- JD 기반으로 강조 포인트와 재작성 후보를 제안한다.
- 변경 이유와 근거를 함께 제시한다.

사용자가 얻는 결과:

- 맞춤 이력서 초안
- 변경 diff
- 수정 이유
- PDF 출력본

## 5. MVP 범위

MVP에 반드시 포함할 것:

- PDF 업로드
- 텍스트 추출
- 추출 텍스트 확인 및 수정 단계
- JD 입력
- JD 구조화
- 맞춤 재작성
- 변경 diff 표시
- 수정 이유 및 근거 표시
- PDF 출력

MVP에서 제외할 것:

- 합격 가능성 예측
- 허위 사실 생성
- 복잡한 버전 관리 시스템
- 자동 대량 크롤링
- 자기소개서/포트폴리오 확장
- 꼬리물기 질문 학습 기능

MVP 이후 확장 후보:

- 약한 수준의 공고 추천
- 부족 역량 분석
- 직무별 상세 rubric 확장
- 공고별 버전 관리 고도화

## 6. 재작성 정책

허용:

- 표현 강화
- 구조 재배치
- JD에 맞춘 강조 순서 조정
- 기존 사실을 더 명확하게 드러내는 문장 개선

금지:

- 없는 경험 생성
- 없는 수치 생성
- 역할 부풀리기
- 검증되지 않은 성과 단정

원칙:

- 사실은 유지한다.
- 사용자가 최종 수정권을 가진다.
- 결과는 반드시 근거와 함께 제시한다.

## 7. 주요 가정과 리스크

핵심 가정:

- 경력직 백엔드 개발자는 공고별 맞춤 이력서에 가장 큰 가치를 느낀다.
- 사용자는 편집 가능한 중간 단계를 선호한다.
- PDF 기반 텍스트 추출로도 v0 경험을 충분히 만들 수 있다.

주요 리스크:

- OCR/파싱 오류로 인한 품질 저하
- 평가 및 재작성 결과의 일관성 부족
- 사실 오류 검출 실패
- JD 구조화 품질 편차

리스크 완화 아이디어:

- 텍스트 확인/수정 단계 제공
- schema 기반 구조화
- rewrite policy 강제
- diff와 근거 표시

## 8. MVP 성공 기준

MVP가 유효하다고 판단하는 기준:

- 사용자가 공고 맞춤 이력서 초안을 빠르게 만들고, 제한된 수정만 거쳐 출력까지 진행한다.

초기 확인 방법:

- 생성 완료 시간 측정
- 사용자 수동 수정량 측정
- 재작성안 수용률 측정
- 사실 오류 검출률 측정

출시 전 꼭 확인할 조건:

- 재작성 정책이 프롬프트와 후처리에서 일관되게 강제된다.
- OCR 실패와 구조화 실패를 분리해서 다룰 수 있다.
- 근거와 diff가 사용자가 이해 가능한 수준으로 제시된다.

## 9. 구현 제약

시간 제약:

- v0는 핵심 흐름만 닫는 방향으로 제한한다.

인력 제약:

- 초기에는 광범위한 직무 확장보다 백엔드 직군에 집중한다.

기술 제약:

- PDF 우선
- 로컬 모델 지향
- 자유 레이아웃 편집기 미구현

운영 제약:

- 원본 PDF는 영구 저장하지 않는다.
- 저장 시 PII는 마스킹을 우선한다.

## 10. 현재 결론

지금 시점의 해결안 요약:

- v0의 제품 핵심은 `JD 맞춤 이력서 재구성`이다.
- 다른 기능은 이 핵심 흐름의 품질을 보조하는 역할로 둔다.

실행 계획으로 넘길 핵심 입력:

- MVP 핵심 기능: 업로드, 텍스트 확인, JD 입력, 맞춤 재작성, diff, 근거, PDF 출력
- 제외 범위: 추천/예측/학습/범용 확장
- 선행 확인사항: schema, rubric, rewrite policy, fact-check policy
- 핵심 리스크: 파싱 품질, 일관성, 사실 오류
