# Problem Definition

- 상태: `draft`
- 마지막 수정일: `2026-04-10`
- 작성자: `lsh`

## 1. 한 줄 정의

이 문서는 어떤 문제를 누구를 위해 왜 풀어야 하는지 명확히 한다.

한 줄 요약:

`경력직 백엔드 개발자는 여러 공고에 지원할 때마다 이력서를 공고 맞춤형으로 수정해야 하는데, 이 과정은 시간이 많이 들고 품질 편차가 크다.`

## 2. 고객 / 사용자

주요 고객:

- 경력직 백엔드 개발자

부가 사용자:

- 신입 개발자
- 장기적으로는 다른 개발 직군

이들이 지금 하려는 일:

- 여러 채용공고에 빠르게 지원하기 위해 공고별 맞춤 이력서를 준비한다.

이들이 중요하게 보는 가치:

- 빠른 지원 준비
- 표현 품질 향상
- 공고 적합도 설명 가능성
- 개인정보 보호

## 3. 문제 상황

현재 어떤 상황에서 문제가 발생하는가:

- 구직자가 여러 공고에 지원해야 하는 시점에 공고마다 이력서를 다시 다듬어야 한다.
- JD를 읽고 어떤 경험을 강조해야 하는지 매번 다시 판단해야 한다.

문제가 실제로 불편한 이유:

- 시간이 많이 든다.
- 표현 품질이 들쭉날쭉하다.
- 어떤 문장을 고쳐야 하는지 스스로 판단하기 어렵다.

문제가 반복되는 빈도 / 규모:

- 대량 지원 기간에 반복적으로 발생한다.

지금 쓰는 대안 또는 우회 방식:

- 직접 수정
- 사람 첨삭
- 컨설턴트
- 범용 챗봇

기존 방식의 한계:

- 시간이 많이 든다.
- 비용이 높다.
- 공고 적합도와 수정 이유를 구조적으로 설명해주지 못한다.

## 4. 왜 지금 풀어야 하는가

지금 이 문제를 풀어야 하는 이유:

- 경쟁이 강한 채용 시장에서는 지원 횟수와 품질을 동시에 관리해야 한다.

지금 풀지 않으면 생기는 비용:

- 지원 준비 시간이 길어진다.
- 공고 적합도가 낮은 이력서를 제출할 확률이 높아진다.
- 반복 작업으로 인해 많은 공고를 놓친다.

## 5. 기대 효과

사용자 측 기대 효과:

- 공고 맞춤 이력서 준비 시간을 줄인다.
- 이력서 문장과 구조의 품질을 높인다.
- 어떤 강점과 약점이 있는지 근거 기반으로 파악한다.

비즈니스 측 기대 효과:

- 반복 사용이 가능한 핵심 흐름을 만든다.
- 향후 공고 추천, 부족 역량 분석, 학습 기능으로 확장할 기반을 만든다.

운영 측 기대 효과:

- 표준화된 입력과 출력 구조를 만들 수 있다.
- 평가와 재작성 결과를 같은 스키마 위에서 다룰 수 있다.

## 6. 성공 판단 기준

성공을 무엇으로 판단할 것인가:

- 사용자가 빠르게 맞춤 이력서를 만들고, 결과를 크게 손보지 않고 받아들이는지 본다.

정성 지표:

- 수정 이유와 근거가 납득되는가
- 사용자가 결과를 신뢰하는가

정량 지표:

- 생성 완료 시간
- 사용자 수동 수정량
- 재작성안 수용률
- 사실 오류 검출률

최소 성공 기준:

- 공고 맞춤 이력서 초안이 10분 내 생성된다.
- 사용자의 추가 수동 수정이 제한된 범위 안에 머문다.
- 명백한 사실 오류가 반복적으로 발생하지 않는다.

## 7. 범위 밖

이번 단계에서 다루지 않을 것:

- 비개발자 직군 확장
- HWP, DOCX, 이미지 업로드 지원
- 허위 사실 생성
- 합격 가능성 예측
- 꼬리물기 질문 학습 기능
- 자동 대량 크롤링

아직 결정하지 않은 것:

- 공고 추천을 v0에 약하게 넣을지 여부
- 백엔드 세부 직무별 rubric 분화 수준

## 8. 열린 질문

- 백엔드 경력직 안에서 우선할 대표 페르소나는 무엇인가
- 수동 수정량을 어떤 방식으로 측정할 것인가
- 사실 오류 검출률을 어떤 방식으로 집계할 것인가

## 9. 현재 결론

지금 시점의 문제 정의 요약:

- 제품의 본질은 `공고 맞춤 이력서 재구성`이다.
- 평가, 분석, 추천은 이를 돕는 기능으로 다룬다.

다음 문서로 넘길 핵심 입력:

- 핵심 고객: 경력직 백엔드 개발자
- 핵심 문제: 공고마다 이력서를 맞춤 수정하는 데 시간이 많이 들고 품질 편차가 크다
- 기대 효과: 빠른 맞춤 생성, 표현 품질 향상, 근거 기반 수정
- 제약 조건: PDF 우선, 사실 유지, 수동 검토 단계 필수
